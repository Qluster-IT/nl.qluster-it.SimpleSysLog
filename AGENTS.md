## App-specific instructions

- BetterLogicLibrary (BLL) is optional for limited app functionality, but is required for full control and the planned widget. Preserve limited-mode operation when the BLL app is not installed, and keep the app settings usable without the bundled BLL assets; do not make either a hard dependency for the existing settings experience.
- Settings and Flow exports opt into JSON/CSV/XLSX streams but must accept buffered results from older BLL versions. JSON exports sort metadata before bounded message reads and preserve native JSON bytes. Skip unreadable entries and report the exact count after successful upload (settings warning popup, Flow app diagnostics); ordinary queries retain best-effort behavior. Generation/upload failures must not announce readiness.
- Keep settings downloads visually unchanged: no download status panels, success messages or manual-link buttons. Show popups only for failures or skipped-entry warnings; missing browser-open acknowledgement or an unused link expiring is not proof of failure.
- The `Automater`, `Automater_log`, and `Automater_condition_log` Flow cards are intentionally hidden, not legacy; scripts use them to generate logging in Flows. Do not change, remove, or repurpose these cards or their behavior without explicit permission.
- Announce API readiness (`/api-ready` and the `api-ready` realtime event) once settings, backlog, retention scheduling and Flow cards are initialized. Do not wait for BLL or its file-backed log storage, because limited mode must remain usable without BLL.
- Missing widget styling capabilities should become designer options, not changes to shared defaults. Match new design requests through design- or theme-specific settings; preserve the appearance of other built-in designs and existing dashboard configurations.
- Journal's App / Group and Facility badges use explicit `elementLineHeights` and a middle-aligned metadata column. Preserve both through validation, rendering, copying and TWF export so badges of different heights share a vertical center regardless of host font metrics.
- The shared `.ssl-widget` line-height baseline is 1.5, matching settings previews independently of host CSS. All designs, including custom ones, inherit it unless an element has its own CSS or `elementLineHeights` override; do not fix host-spacing regressions by adding overrides to each preset.
- Template creation starts the rich Clipboard API write from the user gesture with deferred content before encoding or rendering. Do not auto-copy over insecure HTTP; show manual-copy guidance, keep the forum button disabled until the post is copied, and clear that state when copying only the TWF. Keep the settings view inert behind an accessible progress overlay during generation, restore busy/inert state on all outcomes, and retain legacy and ready-Blob copy fallbacks with focused tests.
- Template images show the complete applicable toolbar, day separators and pager, with all eight severity levels once in syslog order (Emergency through Debug). Expand the image preview instead of clipping or paging away entries; preserve the interactive designer preview's paging.
- Use English for all text in generated template images, including controls, headings, sample entries and formatted dates, independently of the settings, Homey and browser language; interactive previews remain localized. In copied template forum posts, place the light and dark images beside each other in one paragraph at half preview width, not in separate paragraphs.
- The log viewer's interactive date filter is an inclusive optional From/To calendar range. Validate strict `YYYY-MM-DD` dates, apply it to initial and realtime entries (including Android Web-widget requests and polling), and keep it out of signed link configuration.
- Save the log viewer's interactive Level and Date filters app-side per `Homey.getWidgetInstanceId()`, and restore them before the first log query. Keep this state separate from widget settings and signed Android-link configuration.
- Explicit Level selections override the widget's minimum severity. Reset clears those selections and restores the current widget-setting minimum, not all levels. Apply simple/advanced search to history before pagination in native and Android Web widgets, using bounded message reads and the same predicate for realtime entries.
- Interactive Facility uses multi-select checkboxes like Level, with no empty/Reset option in the list; no selection restores the widget's Facility setting. App / Group and Hostname use field-scoped searches following the widget's simple/advanced mode (simple if search is hidden). Each overrides its corresponding widget setting; Reset or clearing the selection restores it. Persist these with the other per-widget filters, accept older single-Facility state, keep them out of signed links, and filter metadata before pagination without reading unrelated messages.
- Keep all facility IDs 0–23 available in Flow card dropdowns, widget settings, interactive filters and the designer preview. Use `assets/js/ssl-facilities.js` for log labels and preserve the existing Security/Console picker aliases for Audit/Alert (13/14). Kernel is numeric `0`; do not treat it as an unspecified facility.
- Advanced search is the default for new widgets; preserve explicit Simple/None choices. On iOS, keep editable widget controls at least 16 px without shrinking larger configured fonts to prevent focus zoom. Disable pinch-to-zoom inside widgets while preserving horizontal and vertical scrolling.
- Height is max height is opt-in. Measure intrinsic displayed content, not the stretched list viewport, and cap Homey.ready height updates at Height. Re-measure after filtering, paging, realtime changes, wrapping and fonts; exclude floating filter menus and stop observers on widget destruction. Keep fixed-height behavior unchanged when off.
- Widget updates default to Live. Periodic mode defaults to 10 seconds (minimum 1), does not subscribe to live entries or start Android long polling, and schedules the next refresh after active queries settle. Preserve immediate interactive queries, bounded page sizes, retries when storage is unavailable, and timer cleanup on destruction.
- Load native widget styles and saved filters concurrently, but restore both and register timestamp formats before querying logs. Reuse the computed card grid for the active design; the editable designer must render its current layout, not a stale grid.
- Keep widget search mode (`none`, simple, advanced) independent of the Show filters setting; filters default on, and turning them off hides and disables interactive date/level filtering. Paging is a separate setting, off by default; when enabled, use Entries per page with Previous/Next navigation and display the paging controls in the designer preview.
- Apply the configured entry limit to every initial, visibility and realtime update; a paging lookahead entry must never be displayed. Live insertions scroll to the top only within 24 px of it; otherwise preserve the visible entry's position. Apply this to both the native list scroller and the Web wrapper's page scroller.
- Previous and Next scroll the native list or Web wrapper page to the top after the new page renders. Do not apply this paging reset to periodic/visibility refreshes, failed or stale requests, or destroyed widgets.
- Use **Design**/**Designs**, not "Design style(s)", for the widget settings and editor labels; keep the translations consistent across supported languages.

## Widget designer details

- Follow the Chronograph designer pattern, adapting only what applies to Simple (Sys) Log.
- Built-in designs and themes (`BUILT_IN_DESIGNS`/`BUILT_IN_THEMES`) are defined in `lib/widget-styles.js`.
- Preserve Default and its stable ID when adding built-in presets. Compact, Journal and Console are additional designs; Ocean, Forest and Sunset are additional themes. Translate their names through `widgets.design`/`widgets.theme` in every supported locale.
- Compact Classic adds the older widget's stacked timestamp/severity rail, wrapping message and App / Group + Facility metadata. Pair it with Default; do not add a duplicate Classic theme or change existing design selections.
- Follow `C:\Users\Qlustrator\.copilot\instructions\homey-colors.md` for shared palette IDs/values, exact Homey token fallbacks, severity mapping and preview parity. Keep `.ssl-widget` and `.ssl-palette` on the same app-prefixed variables, ensure readable badge text, and preserve explicit custom-theme colors.
- Emulate the dashboard token mappings only on settings previews and palette indicators, using the shared mode-aware defaults. Counter-invert interactive previews only when an inspectable host actually applies Homey's inversion. Template images use the shared dashboard backdrop for their own mode, independent of the editor.
- Keep every shared palette ID from `homey-colors.md` available in the named color picker. Default uses app-default severity colors backed by shared CSS variables; Console and Default (Syslog) retain explicit HEX severity colors. Convert the briefly offered Console/Syslog color names to their original HEX values when validating saved themes and templates.
- Aurora is an additional matching design/theme pair: a timestamp rail and top severity-border element, with violet badges and teal accents. Its theme retains Homey's default background, surface and message text.
- WidgetKeeper is a separate design/theme pair inspired by WidgetKeeper's Light Control, Thermostat Presets and Device Values: system fonts, 17/24 headings, 14/20 body text, neutral metadata and blue accents. Keep its styling preset-specific.
- Only the built-in Console theme overrides the widget background. Default, Ocean, Forest and Sunset use Homey's default background and fill; preserve independently configured custom-theme backgrounds.
- Theme `backgroundGradientEnd` optionally supplies the second color of a two-color gradient. Omit it for the original mode-aware fill; keep it editable, validated and portable through theme copies and TWFs.
- Use the shared settings color picker for every color field so each label gets an effective-color swatch. Align non-color options such as Background fill with nearby labels by reserving the swatch space without drawing a dot. Use the widget renderer's gradient endpoint calculation for the App default endpoint swatch.
- Store per-element text overrides as `elementTextStyles: {<element>: {textCase?, weight?, italic?, spacing?}}`. Keep overrides optional and sparse: validate element IDs and values, and omit empty entries.
- Timestamp 2 is independently formatted and styled; only the original Timestamp follows the widget's date/time override. Compact and Compact Classic place the date (Timestamp 2) above the time; Compact keeps both the same size, and only Compact Classic uses a smaller date. Request/register the second format only when placed, including native/Web history, realtime and English template images; preserve it in copies and append TWF keys.
- Timestamp wrapping offers `normal` and `nowrap` only; migrate retired `words` values to `normal`. Do not insert newlines into formatted timestamps. Older custom layouts may need a manual Timestamp 2 adjustment.
- Border width distinguishes Homey default from explicit 0 (borderless, without the dark rim). Preserve older `widgetBorderWidth: 0` as default unless `widgetBorderless` is true. Keep `widgetPadding` per side, row `columnGap`, column `elementGap` and `elementLineHeights` optional so existing layouts keep their appearance. Use the shared `widgetStyle` helper for frames, colors and background fill in widgets and every preview; validate HEX colors as `#RRGGBB`. In the Web wrapper, isolate the log list so day-separator labels stay beneath the sticky toolbar's filter menu.
- Apply runtime `widgetStyle` properties with `sslWidgetStyle` and `style.setProperty`, not AngularJS `ng-style`, which does not apply the CSS custom properties. The Web wrapper scrolls the page itself: keep its viewport frame and unpaged bottom inset fixed while preserving configurable borders and padding.
- Order the designer grid as Widget, Search and filters, Day separator, Entry (above its log-card rows), then Paging. Entry selects and outlines every visible log card, not the widget frame or day separators. Put Entry background and Border under Entry in Theme mode. Keep the existing `colors.surface` and `colors.border` values and rendering for built-in and custom themes and TWFs. Keep Widget border (`colors.outline`) under Widget.
- Show the entire current preview page before pinning. While pinned, cap the visible preview height and reserve the difference from its measured pre-pin height below it, outside the preview. Keep editor spacing constant across the threshold. Reserve the settings tabs' height separately with the scroller's spacer, not scroller padding, which offsets the sticky preview.
- Search and filters and Paging have independent optional 1–2 row layouts (`toolbarLayout`/`pagingLayout`), with drag restricted to each area. Missing layouts retain the original toolbar/pager markup. Their elements reuse sparse text/theme overrides; `controlStyles` holds optional height, paddingX, paddingY and radius overrides. Widget settings still gate search, filters and paging. Append TWF keys without reordering.
- Draw the Paging selection outline inside the preview footer so the widget's clipped, rounded frame does not hide its sides or bottom edge.
- The day separator has an optional 1–2 row sub-grid with its own element IDs and may have no elements. Its elements are Date and Line. Date supports the same sizing, font, format and theme color as other elements. Line has a design-level position (behind, above or below the other elements in its cell, configured on the Line), thickness (1–10 px), style (solid, dashed, dotted or double), and theme color only. Behind follows the cell's vertical alignment; above/below use a full-width line. The default is one centered column with the date on a middle line; missing sub-grid data gets that default during validation. Append TWF keys; never reorder them.
- The four interchangeable severity borders (Border 1–4) are design elements that can be placed independently, including more than one at a time. Each has a design-level side (left/top/right/bottom) and thickness (1–10 px), and only a theme color (defaulting to severity/accent). When a border column covers an entire card edge, render it as the card's own border so it follows rounded corners and compensate padding so content does not shift; otherwise, border only that column. The built-in default places one border in the first column of the first row, spanning all rows.
- In the log list, share content-sized (`auto`) grid track widths across all log cards and day separators so time and level columns align. Mark tracks with CSS variables, then coalesce measurements after rendering, on resize, and after fonts load, setting each variable to the widest value.
- SSL TWFs use `lib/widget-template.js` with `/widget-template/encode` and `/widget-template/decode`. The Widget Exchange(r) catalog uses the dedicated SSL community topic through `lib/widget-template-catalog.js` at `/widget-template-catalog`, with bounded requests and validation of every returned template.
- The current SSL TWF version is v1: `[twf:SimpleSysLog:LogViewer:DESIGN|THEME|DESIGN,THEME:"<payload>":/twf]` with a Brotli-compressed, key-shortened `{v:1,d?,t?}` body. Require the LogViewer family; reject unreleased v2, family-less headers and uncompressed prototypes. Version changes are independent of other apps and stored widget collections.
